## P1 — fix first

### 1. Admin auth fails OPEN if `ADMIN_TOKEN` is ever unset
`api/server.js:36-40`

```js
if (token) return req.headers["x-admin-token"] === token;
return ["127.0.0.1", "::1"].includes(req.ip); // no token set → localhost only
```

That comment is wrong behind the reverse proxy. Fastify is constructed without
`trustProxy` (`server.js:12`) and nginx proxies from `127.0.0.1` on the **same
container**, so `req.ip` is `127.0.0.1` for *every request on earth*. With no token
set, `GET /api/admin/rsvps.csv` returns the full guest list — names, emails, phones,
private messages — to anyone.

**Not currently exploitable**: prod has a token set (verified: prod answers 401 with
no token and with a wrong token). The danger is that `api/.env.example` contains **no
`ADMIN_TOKEN` line at all**, and `deploy/app-ct-setup.md:18` says `cp .env.example .env`
— so a container rebuild that follows our own runbook silently publishes guest PII.

**Fix:** add `ADMIN_TOKEN=` to `.env.example`, and change the fallback to fail *closed*
(no token → refuse, log loudly). Optionally set `trustProxy` so logs carry real client IPs.

## P2 — real bugs, guest-visible or data-corrupting

### 2. The RSVP page tells guests to do the one thing that corrupts the guest list
`web/src/rsvp.njk:80` promises: *"Need to change anything later? Just send the form
again with your update."* But `api/server.js:70-80` inserts a **new** household + guest
+ rsvp row on every POST — no upsert, no dedupe key — and the admin endpoint sums every
row (`server.js:110`). A guest who follows the instruction is counted twice, with the
stale answer still feeding the headcount. Verified on dev: three identical submits →
ids 7, 8, 9.

**Fix:** either dedupe server-side (upsert on name+contact, or last-write-wins) or change
the copy to "text us and we'll update it."

### 3. Registry thank-you lies when the request fails
`web/src/registry.njk:32-33`: `try{ await fetch(...) }catch(_){}` then an unconditional
`this.sent=true`. Wifi drop, API down, or a 500 all still render "Thank you so much!
We'll be in touch." The guest believes the couple was told; nothing was stored.

### 4. RSVP form blames the guest for server errors
`web/src/rsvp.njk:19-21` maps *every* non-2xx to `error='form'` → "Something in the form
needs another look." When the API hits its own 500 path (DB locked, disk full), the guest
re-reads their perfectly good answers, retries, and the RSVP is lost. Distinguish 4xx
(their input) from 5xx (our problem).

### 5. CSV export is formula-injectable
`api/server.js:122` escapes by doubling quotes only. A guest whose name or song starts
with `=`, `+`, `-`, or `@` produces a live formula when Carolyn opens `rsvps.csv` —
and opening that CSV is the intended workflow. Verified: `=HYPERLINK("http://evil.example","click")`
round-trips intact. **Fix:** prefix cells matching `^[=+\-@]` with `'`. Add a UTF-8 BOM
while there (emoji/accents currently mangle in Excel on Windows).

### 6. Party size is unbounded server-side
`api/server.js:57,67`: `party` has no maximum; `Math.max(1, parseInt(...) || 1)` accepts
anything. The form's `max="10"` is client-side only. One curl set the dev headcount to
over a billion. This is the number the couple caters from.

### 7. Registry acknowledgements are write-only
`registry_contributions` has an INSERT (`server.js:96`) and **no read endpoint anywhere**
— admin exposes only `/api/admin/rsvps[.csv]`. The page promises "Let us know below so we
can thank you properly," and the answer lands where only a manual `sqlite3` session reaches
it. The form also never sends `method`, so that column is always NULL.

### 8. `/api/registry/ack` has no schema and no try/catch
`api/server.js:92-99` — the only route without validation. `{"name":{"a":1}}` → **500**
leaking `ERR_INVALID_STATE: Unknown named parameter 'a'`. No length caps either: a
500,000-char `note` was accepted and stored, bounded only by nginx's 1 MB body limit.

### 9. SMS webhook path mismatch — breaks the day Twilio goes live
Code registers `app.post("/sms/webhook")` (`api/server.js:129`); nginx and every runbook
route `/sms-webhook` (hyphen). Both externally reachable paths 404 today. Whichever path
Twilio is pointed at, inbound SMS fails silently.

### 10. Gallery hero: the title now sits on Carolyn's face
Regression from today's crop fix. `background-position:center 20%` brought the faces into
frame but put the centered "Gallery" heading directly over the bride's face at every
width, and at 1920px the groom's head clips the hero's top edge again. Both visual
auditors flagged it independently. **Fix properly:** move the text off the faces (left-align
the hero stack, or add a text panel) rather than nudging the percentage again — the same
photo has to serve 320px through 1920px.

### 11. Nine of ten pages share one generic meta description
Only `/eat/` has its own. Every other page shows "We can't wait to celebrate with you on
the coast of Maine" in search results and link previews — including `/travel/`, `/stay/`,
and `/rsvp/`, the pages guests actually search for. Add a `description` per page front matter.

### 12. Skip link is invisible when focused (WCAG 2.4.7 AA)
`style.css:296` defines `.sr-only` with no `:focus`/`:focus-visible` reveal anywhere in
the file. "Skip to content" is the first tab stop on every page, so a keyboard user's very
first Tab sends focus into an unseeable 1px box.

## What shipped (2026-08-02, same day)

All findings above were fixed, built clean, and **deployed to DEV**
(`merrolyn.moorelab.cloud`), verified over HTTPS: 10/10 pages 200, branded 404
returns 404 with our page, robots.txt + sitemap live, admin refuses without a
token and answers with one, per-client rate-limit buckets confirmed at the origin,
and an end-to-end RSVP re-submit updated one row instead of creating a second.

Three commits: `fix(api)`, `fix(forms)`, `fix(site)`.

### Notes on how some were fixed, where it differs from the finding

- **Registry tile font (P3, desktop finding 4)** — NOT changed. The tile labels are
  `<b>` elements, not headings, so Mulish is correct under the house rule ("one text
  voice; Cormorant on headings only"). Only the vertical alignment was fixed.
- **Gallery hero (P2)** — fixed by changing the photo rather than the crop. The band
  is short and the title stack is centred, so any centred face loses either way; the
  ring detail shot has nothing to collide with at any width.
- **Card bottom alignment** — the first attempt pinned *any* trailing paragraph and
  stranded plain closing text ("Alternate: Boston Logan…") at the bottom of tall
  cards, which was worse than the original. Narrowed to `:has(a)` so only link rows
  move; degrades to the old behaviour without `:has()` support.
- **Rate limiting** — nginx was overwriting `X-Forwarded-For` with HAProxy's address,
  so enabling `trustProxy` alone would have put every guest in ONE bucket and let a
  single burst throttle the whole internet. nginx now appends, and the limiter keys on
  `CF-Connecting-IP` (the one address Cloudflare guarantees). Verified at the origin:
  client A hit 429 at 30 requests while client B still got through.
- **Dead assets** — moved to `web/assets-archive/`, not deleted. They are the couple's
  photos and logo art; they just stop shipping to the containers.
- **Gallery masonry ragged bottom edge (P3)** — NOT fixed. Uneven column tails are
  inherent to a CSS-columns masonry with mixed aspect ratios; any fix is worse than
  the symptom.
- **Phone-format inconsistency (P3)** — NOT changed after review. `(207) 729-3688`
  vs `1-800-646-0068` is the conventional distinction between local and toll-free,
  and the Registry's `774-275-1800` is a Zelle handle, not a callable number.
- **Venue website link (P3)** — left alone deliberately. Carolyn asked for the inn to
  come off the public page, so adding a link to it elsewhere would cut against that.
